# Core Processes Matrix

Major processes of the Level-0 DFD for the Property Viewing and Rental Application System. The processes P1 to P6 and the data stores D1 to D5 are the same as in the Level-0 DFD.

| Process No. and Name | Input Data | Output Data | Rules |
|---|---|---|---|
| P1 - Manage Accounts and Authentication<br>(UC-13, UC-14) | Registration & Login Details (from Tenant, Landlord): email, password, role<br>Admin Login Credentials (from Admin)<br>Account Records (from D1): stored password hash, role, account status, failed-login count | Account & Login Confirmation (to Tenant, Landlord)<br>Login Confirmation (to Admin)<br>Account Records (to D1): new account, updated failed-login count or lockout | 1. Registration is open to tenants and landlords only (UC-13). Admin accounts are not self-registered (A-7).<br>2. A password needs at least 8 characters with one number and one special character (NFR-15). Invalid input gets inline feedback within 1 second (NFR-13).<br>3. Passwords are stored only as a one-way hash, never in plaintext (NFR-07).<br>4. Login succeeds only if the email and password match a stored account (FR-14) and the account is not suspended (FR-17, A-5).<br>5. 5 consecutive failed logins lock the account for 15 minutes (NFR-11).<br>6. The role found at login decides which processes the user can reach. Admin access is checked again on every admin request (NFR-16, A-1).<br>7. Login is mandatory before listing, booking or applying (R-01, R-02, R-03). |
| P2 - Manage Property Listings<br>(UC-01, UC-02) | Listing Details & Photos (from Landlord): location, price, property type, amenities, photos, availability<br>Listing Records (from D2): the existing listing when it is edited | Listing Confirmation (to Landlord), or an error message when validation fails<br>Listing Records (to D2): new or updated listing | 1. Only a logged-in landlord can create or edit a listing (R-03, FR-01, FR-02).<br>2. A listing needs location, price, property type, amenities and photos (FR-01). A submission with missing required fields is rejected with a clear error message (NFR-02).<br>3. At most 10 photos per listing, each at most 5 MB (NFR-05).<br>4. A landlord can edit only their own listings (ownership is implied by "their listings" in FR-04 and FR-12).<br>5. A saved listing is stored in D2 and becomes searchable (S-02).<br>6. Edits may change details such as price, availability and description (UC-02). |
| P3 - Search and View Listings<br>(UC-06, UC-07) | Search Criteria & Listing Selection (from Tenant): location, price range, property type, chosen listing<br>Listing Records (from D2): matching listings | Search Results & Listing Details (to Tenant): result list with key details, then photos, price, location, amenities and availability of the chosen listing | 1. Tenants can filter by location, price range and property type (FR-06).<br>2. Selecting a listing shows photos, price, location, amenities and availability (FR-07).<br>3. Results can be sorted by price (S-01).<br>4. A search with no matches returns an empty-result message, not an error (no-results case in Risk R2).<br>5. Listings removed by an admin are never returned (FR-19).<br>6. Results are returned within 2 seconds for a catalog of up to 10,000 listings (NFR-06). |
| P4 - Manage Viewing Appointments<br>(UC-08, UC-11, UC-12, UC-15) | Viewing Availability Slots, Cancel / Reschedule Request, Viewing Calendar Request (from Landlord)<br>Viewing Booking Request (from Tenant)<br>Listing Records (from D2)<br>Slot & Appointment Records (from D3) | Available Viewing Slots, Viewing Confirmation & Change Notice (to Tenant)<br>Booking Confirmation, Viewing Calendar (to Landlord)<br>Slot & Appointment Records (to D3) | 1. A landlord defines the available time slots of a listing (FR-11). A tenant can book only one of these slots (FR-08).<br>2. A tenant must be logged in to book (R-02).<br>3. A slot can be booked by only one tenant at a time (FR-13), so a booked slot is no longer offered.<br>4. When a booking is confirmed, both tenant and landlord receive a confirmation (S-03). The appointment is saved within 1 second and survives a server restart (NFR-12).<br>5. Only the landlord cancels or reschedules a viewing, and the tenant is notified of the change (FR-15).<br>6. The calendar lists all upcoming viewings across the landlord's listings (FR-12) and loads within 2 seconds for up to 50 appointments (NFR-14). |
| P5 - Process Rental Applications<br>(UC-03, UC-04, UC-05, UC-09, UC-10) | Rental Application Details, Withdrawal & Status Requests (from Tenant): personal details, desired move-in date<br>Application List Request, Application Decision (from Landlord)<br>Application Records (from D4)<br>Listing Status (from D2) | Application Confirmation & Status (to Tenant)<br>Submitted Applications, Decision Confirmation (to Landlord)<br>Application Records (to D4)<br>Listing Status update (to D2) | 1. A tenant must be logged in to apply (R-01). An application contains personal details and the desired move-in date (FR-09).<br>2. A tenant can have only one active application per listing (FR-10).<br>3. An application is in one of four states: submitted, accepted, rejected, withdrawn (UC-10, FR-03, A-4).<br>4. A tenant can withdraw an application only before it is accepted or rejected (FR-03).<br>5. A landlord sees only the applications for their own listings (FR-04) and accepts or rejects one, which updates its status (FR-05).<br>6. Accepting an application closes the listing to new applications (S-04), so P5 updates the listing status in D2.<br>7. A tenant can check the current status of their own applications (UC-10). |
| P6 - Administer Platform<br>(UC-16, UC-17, UC-18, UC-19, UC-20) | Account Action (Suspend / Reactivate), Listing Flag, Listing Removal Decision, Admin View Requests (from Admin)<br>Account Status (from D1)<br>Listing Records (from D2)<br>Application Counts (from D4)<br>Flag & Action Log Entries (from D5) | User Account List, Flagged Listings Log, Activity Statistics, Action Confirmation (to Admin)<br>Account Status update (to D1)<br>Listing Records & Removals (to D2)<br>Flag & Action Log Entries (to D5) | 1. Only an admin can reach this process, and the admin role is checked on every request, not just at login (NFR-16).<br>2. The admin locates the account in the user list before suspending or reactivating it (R-04). A suspended account cannot log in (FR-17, A-5). The list is paginated for up to 10,000 accounts (NFR-20).<br>3. Listings flagged as duplicate or inappropriate appear in the flagged listings log (FR-18). The admin raises the flag after a report received outside the system (S-05, A-2).<br>4. A listing is removed only when the admin's review of the flagged log confirms a policy violation (R-07, FR-19).<br>5. Every suspend, reactivate, flag and removal action is logged with a timestamp and the admin ID, and kept for at least 1 year (NFR-17, S-05).<br>6. Statistics cover active listings and applications submitted this week (FR-20) and are never older than 5 minutes (NFR-18). |
